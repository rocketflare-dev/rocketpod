# Middleware

Applied globally in `src/api/index.ts` in THIS order. Each step needs what the earlier
ones set; reordering silently breaks something.

| # | File | Sets / does | Why here |
|---|------|-------------|----------|
| 1 | `error-handler.ts` | `app.onError` + `app.notFound` → shared envelope `{ error, statusCode, code?, details? }` | Registered first so even a config failure gets the envelope |
| 2 | `request-logger.ts` | `requestIdMiddleware` + `requestLogger` → `requestId`, `logger` (hono-pino) | Every later log line, including config errors, has a request id. The one middleware that runs before config, so it calls `loadConfig` itself and falls back to `info` |
| 3 | `config.ts` | `config` = `loadConfig(c.env)` | Everything below reads `c.get('config')`, never `c.env` |
| 3b | `platform.ts` | `platform` = `resolvePlatform(c.env)` — the prebuilt `env.PLATFORM` the entry built, else `EMPTY_PLATFORM` | Everything below reads jobs, storage, realtime, runs, rate limits and AI from `c.get('platform')`, never a capability off `c.env` |
| 4 | `security-headers.ts` | Headers after `next()`; HSTS carries `includeSubDomains` on `APP_URL`'s host only; **a 101 is returned untouched** (the realtime hub's upgrade response must reach the server as-is; re-wrapping a 101 drops the socket). A response on a public site host gets `publicSiteCsp` (`publicSiteCsp()`, strict plus what the site declared; scripts and styles load from `<request origin>/site-assets/`, never `'self'`; forbidden sources and script sources reaching `/assets/` are dropped). Otherwise ONE second branch: a response whose route set `c.set('embeddable', true)` gets `X-Frame-Options: SAMEORIGIN` + `EMBEDDABLE_CONTENT_SECURITY_POLICY` (`frame-ancestors 'self'`) instead of `DENY` + `'none'`, so the document viewer can frame a PDF. **Only a route that has PROVED the content type may set it** (`routes/files.ts`: `isEmbeddableMimeType(row.contentType)`, set BEFORE the `If-None-Match` 304 return, or a revalidation from inside the `<object>` kills the embed) — never a path allowlist, never a global policy change; both policies build from one `CSP_BASE` so they cannot drift | Early so 4xx/5xx from later middleware are covered too |
| 5 | `body-limit.ts` | `jsonBodyLimit` 1 MB on `/api/*`, `/auth/*`, `/mcp` and each plugin `apiPrefixes` entry outside `/api` → 413 `payload_too_large`; **skipped for the `UPLOAD_PATHS` and a plugin's `uploadPaths`** (`/api/files`, `/api/ai/documents/upload`; `isUploadPath`) — each mounts `uploadBodyLimit` (`MAX_UPLOAD_BYTES + 64 KB` multipart overhead) on its `POST` and enforces the exact per-file cap in the handler; a plugin public mount's `bodyLimitBytes` (≤ `MAX_PUBLIC_MOUNT_BODY_BYTES`, 10 MB; `publicBodyLimitOverrides`) replaces the 1 MB cap beneath its prefix (`apiBodyLimit`, `public-mounts.ts`, which also rate-limits each public mount per IP at the mount) | Before any parsing or DB work; the upload cap is per route so one route's multipart need does not lift the JSON cap everywhere |
| 6 | `cors.ts` | Function origin from `config.APP_URL` (+ outside production: the :3000/:3001 dev origins and the loopback twin of `APP_URL` and of the request's own loopback origin, so custom `DEV_UI_PORT`/`DEV_API_PORT` need only `APP_URL` to follow; `csrf.ts` reads the same `allowedOrigins(cfg, c.req.url)`); **bypassed when `Upgrade: websocket`** (`isWebSocketUpgrade`) — CORS does not govern the handshake and `cors()` would try to set headers on the 101. `/mcp` and `/.well-known/oauth-protected-resource*` get `mcpCors` instead: any origin, NO credentials, `WWW-Authenticate` exposed — a browser MCP client calls them cross-origin with a Bearer token, and the cookie is never a credential there | Must answer preflights BEFORE csrf can reject them |
| 7 | `csrf.ts` | Origin/Referer/Sec-Fetch-Site check for cookie-authed unsafe methods → 403 `csrf_failed` | Cookie-only, no DB: cheap rejection before we open a client |
| 8 | `database.ts` | `db` per request from `openDatabase` (a view of the Node process pool), closed via `deferOrAwait`; exports `deferOrAwait(c, fn)` (= `c.executionCtx.waitUntil`, which `src/node/server.ts` backs with its tracked defer set (`node/defer.ts`, drained on shutdown) — awaited inline when there is no execution context, as under `app.request` in tests) | Last global: first thing with real cost |
| 9 | `public-sites.ts` | On a host a plugin's `publicSites.hosts(config)` claims (from the request URL's own host, which `@hono/node-server` builds from `Host`; never a forwarded header): the plugin's router answers everything, so `/api/*`, `/auth/*`, `/ws` never reach core there. GET/HEAD plus POST on a declared form path, else 405. Pages are never rate limited; a declared form POST has `rateLimit()` (default `PUBLIC_MOUNT_RATE_LIMIT`) and its own body cap. Sets `publicSiteCsp`, which `security-headers.ts` applies, and strips a page's `PUBLIC_SITE_PAGE_CSP_HEADER` after merging it. `publicSites.cache` uses `caches.default` when the runtime has one — a Node process does not, so it is inert. A `hosts` returning `null` (dormant) gives a plain uncached 503 on every host but APP_URL's and loopback. A claim on APP_URL's host, or a second claim on a host, is ignored and logged. With no plugin declaring `publicSites` it is a pass-through | After `database` so the plugin's router gets `db` (postgres.js connects on the first query). Before `tracing` and every mount so a site host can reach none of them |
| 10 | `tracing.ts` | `tracerMiddleware` on `/api/*` — `tracer` = `tracerFor(config, { store: ownConnectionSpanStore(config) })`: the span recorder with the OTLP exporter when a backend is configured (`exporterSettings`) plus the `ai_spans` store, which opens its OWN short-lived client per non-empty flush because the request's may already be closed; `noopTracer` only when neither sink exists; after `next()` the batch is flushed through `deferOrAwait` (never on the response path). `withAuth` exposes it as `tracer`; a bare router without it falls back to `noopTracer` | Needs `config`; must wrap the handler so a flush follows every traced call. Streaming routes flush again themselves inside the stream — flushing an empty batch is a no-op |
| — | `auth.ts` | `authMiddleware` (cookie `__Host-session` OR `Authorization: Bearer <api key>` → `auth: AuthContext`; a Bearer key's scopes are enforced here — `read` allows safe methods, `write`/`*` everything, else 403 `insufficient_scope`; ONE LATERAL query; sliding expiry via `fireAndForget` → `deferOrAwait`) and `globalAdminMiddleware` (cookie + `isGlobalAdmin`, tenant-free); `resolveCookieAuth(c)` is the exported cookie half that `routes/ws.ts` calls itself, after its own `Origin` check against `allowedOrigins` | Applied PER MOUNT in `index.ts`, never inside route files: the public surface (health, `/auth/*`, `/api/identity/events` — signed, `/api/invite/:token`, `/ws` — which cannot carry headers and so authenticates inline, plugin `/api/hooks/<id>`) is enumerable and small |
| — | `feature.ts` | `requireFeature(name)` → a middleware for the optional THIRD element of a mount-table entry in `index.ts`; 404 `feature_disabled` (not 403 — that would confirm the feature exists) when `auth.features` lacks it. Reads the ARRAY, never the ability: `manage all` covers every `Feature:` subject | After `authMiddleware` on the same prefix, because it reads what that sets |
| — | `permissions.ts` | `guardPermission` / `can` / `guardOwner` / `isAdminLevel` over `auth.ability`; `guardPermission` throws `UnauthorizedError`/`ForbiddenError` and returns the `AuthContext` | Called inside handlers after `withAuthAndDb(c)` |
| — | `rate-limit.ts` | `authRateLimit` (sliding window over `platform.rateLimiter` — the `rate_limits` table — 10/min/IP, no-op without one), `operationLock(locks, key, fn)` per-tenant mutex over `platform.locks` | Mounted on login-shaped routes in `routes/auth/index.ts` and on invite accept in `index.ts` |

Auth codes (envelopes): 401 `unauthorized` · 403 `blocked` · 403 `tenant_suspended` (middleware) · 403 `no_tenant` / `pending_approval` (thrown by `withAuthAndDb` when a valid session has no membership, so tenant-free routes using `withAuth` keep working) · 404 `tenancy_mode_single` (`requireMultiTenant`). AI (thrown by services, not middleware): 503 `ai_not_configured` (`AiNotConfiguredError`, `services/ai/errors.ts`) · 503 `agent_runs_not_configured` · 409 `agent_run_active` · 409 `interrupt_not_pending` (somebody else answered first — the compare-and-set lost, and the UI renders it as that rather than as an error) · 409 `run_not_awaiting_input`.
`rate-limit.ts` also exports the generic `rateLimit({ name, max, windowSeconds })`; `routes/ai-config.ts` mounts it (`ai-test`, 10/min/IP) on `POST /api/ai/config/test` because every call spends provider money. `public-mounts.ts` builds on it for plugin public mounts: `mountPublicRoutes` puts a per-IP limiter (bucket `hooks:<prefix>`, default `PUBLIC_MOUNT_RATE_LIMIT` 120/60 s, `rateLimit: false` opts out) in front of every `/api/hooks/<id>` router, all limiters registered before any router.

Constraints:
- Nothing in `src/` outside `src/node/` (the Node entry) reads `process` or imports a Node server module (`node:fs`, `node:http`…; the portable `node:async_hooks`/`node:crypto` are fine) — `tests/config/platform-seam.test.ts`. Runtime capabilities come from `c.get('platform')`; config from `c.get('config')`; the client IP from `clientIpOf(c)` (`utils/routes/client-ip.ts`).
- Errors are THROWN (`utils/core/errors.ts`), never hand-rolled `c.json({ error })`; `error-handler.ts` is the single place they become responses.
- Anything trusting `c.get('auth').tenantId` is safe; anything reading tenant ids from the request body/query is not.

## Adding one

1. `export const xMiddleware = createMiddleware<AppEnv>(async (c, next) => { ... })` — typed via `AppEnv`, never a bare `Context`.
2. Add a `Variables` field to `src/api/types.ts` if it sets context.
3. Insert it in `src/api/index.ts` at the step whose inputs it needs, update the table above, and add a test in `tests/api/`.
