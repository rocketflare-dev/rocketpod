# `example-feature` — the reference plugin

**It exists to be read first and deleted second.** Between its four published entries it exercises
every slot the seam has, on the smallest thing that could need one: a notes list. Nothing in the
host depends on it. `../CLAUDE.md` is the seam it plugs into.

| Slot | Here |
|---|---|
| `SharedPlugin.features` | `example-feature`, one flag gating the nav item, the page, the mount, the agent tool and the welcome note (core ships none) |
| `SharedPlugin.subjects` | `ExampleNote`, granted per role by `ServerPlugin.grants` — admin-level `manage`, member `read` + `create` |
| `SharedPlugin.jobs` | `example-feature.ping`, the smoke job; the shortest handler in the repo is `jobs/ping.ts` |
| schema | `example_notes` — `tenantRef()` + `timestamps()` + `tenantIsolation()`, indexes led by `tenant_id`; migration `0001_plugin-example-feature-0.1.0.sql`, generated by the HOST |
| `ServerPlugin.mounts` | `/api/example-feature` CRUD behind `requireFeature(EXAMPLE_FEATURE_FLAG)` — the gate is on the MOUNT, 404 not 403 |
| `ServerPlugin.publicMounts` | `/api/hooks/example-feature/ping` — NO session: `POST /api/example-feature/ping-link` mints a `signState` URL carrying the tenant, the public handler `verifyState`s it, re-checks the flag with `ctx.features(tenantId)` (no `requireFeature` can run without auth) and enqueues. The shape of every consent callback and webhook |
| `ServerPlugin.loginMethods` + `identityFor` | **development only**: "Example SSO" on the login page → `/api/hooks/example-feature/sso/start?email=` plays an IdP (signs a pretend assertion with `signState`) → `/sso/callback` verifies it and returns `identityFor(c, id).signIn(...)`. `tests/api/identity.test.ts` also drives `provisionFor` |
| `ServerPlugin.jobHandlers` | `jobs/ping.ts`, checked to cover exactly the variants the shared half declared |
| `SharedPlugin.events` + `ServerPlugin.eventHandlers` | `example-feature.note.created`, emitted by `POST /notes` with the key `note:<id>`; `events/note-created.ts` audits it (idempotent on the note); listed in `plugin.json` `"events"` |
| `ServerPlugin.agents` / `prompts` + `triggers` / `bindable` | `example-feature.note-stats` (`agents/note-stats.ts`, no model call): TRIGGERED by the event unless the title starts "draft", and BINDABLE to it for a picker |
| `ServerPlugin.agentTools` | `list_example_notes` on an agent run's `ctx.tools` only while the run's organisation has the flag (`ToolCtx.features()`), bound to the run's `AccessScope` |
| `ServerPlugin.hooks` | `onTenantCreated` (one welcome note, only when the new organisation starts with the flag, idempotent by "only when there are none") and `seedDemo` (two notes + the flag at 50 % rollout) |
| `UiPlugin.routes` / `nav` | `/example-feature`, `lazy()`, above the core "Organisation" group; route and nav share ONE guard |
| `UiPlugin.queryKeys` | `example-feature:notes` — the same string the server's `entity.changed` nudge carries, declared once in `shared.ts` |
| `CliPlugin.register` | `rocketpod example-feature ping` and `… notes list` |
| `"skills"` | `example-feature` → `.claude/skills/example-feature/SKILL.md`: how to exercise this plugin (flag, notes, ping, public link). Vendored, so it lives in the host's tree at its installed path; a plugin REPOSITORY ships it at `skills/example-feature/` |
| its own tests | `tests/{api,ui,config}/`, discovered by the host's projects; the api one pins that tenant B can neither list, read nor delete tenant A's notes |

**`ctx.interrupt` is not demonstrated here** — the built-in agent examples cover it; this plugin is
about the seam. **`api/hooks.ts` reaches the core `feature_flags` through `allTables()`**
(`@/plugins/api/peers`), called INSIDE `seedDemo`, never at module scope (a cycle —
`../CLAUDE.md` § Boundaries).

## Deleting it

That is the point of it, and it is the check that the seam works: `pnpm plugin remove
example-feature` (plan, then `--apply` — `/rp-plugin` §5), then `pnpm db:generate` (emits `DROP
TABLE "example_notes"`; read it, then `pnpm db:migrate`), then `pnpm gate`. Nothing else in the host
names it.
